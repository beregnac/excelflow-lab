## Задание 1: Публикация сайта и интеграция рекламного блока

### 1.1. Выбранная платформа и обоснование
Для публичного доступа к приложению **ExcelFlow** (Vue 3 + Vite + Tailwind CSS v3.4+) использован **GitHub Pages** (`https://beregnac.github.io/excelflow-lab/`), а в качестве основной рекомендованной платформы для коммерческого сценария проект также подготовлен и развёрнут на **Cloudflare Pages** (`https://excelflow-lab.pages.dev`). GitHub Pages допускает умеренное размещение баннеров и спонсорских блоков на личных и проектных сайтах (при условии, что сайт не ориентирован преимущественно на коммерцию или рекламу) и стабильно открывается во всех сетях, включая сети провайдеров, ограничивающих `*.pages.dev`. При масштабировании монетизации проект без изменения кода переносится на Cloudflare Pages, где условия обслуживания (*Self-Serve Subscription Agreement*) вообще не содержат запретов на рекламу и не ограничивают трафик.

### 1.2. Конфигурация проекта и пошаговое развёртывание
1. В файле `vite.config.js` настроена переменная `base: process.env.VITE_BASE_PATH || '/'`: на корневых доменах (`localhost`, `*.pages.dev`) используется `'/'`, а при сборке в GitHub Actions для репозитория `excelflow-lab` автоматически подставляется `'/excelflow-lab/'`.
2. В `src/router/index.js` передан `createWebHistory(import.meta.env.BASE_URL)` и добавлено копирование `dist/index.html` в `dist/404.html` в `.github/workflows/deploy.yml`, чтобы все маршруты SPA работали корректно при обновлении страницы.
3. Интегрирован компонент `src/components/AdSlot.vue` с поддержкой пресетов размеров (`banner`, `leaderboard`, `sidebar`, `square`, `fluid`) и пользовательских пропсов `width`/`height`. Блок размещён на главной странице (`HomeView.vue`), в каталоге (`CatalogView.vue`) и в документации дизайн-системы (`DesignSystemView.vue`).
4. Автоматическое развёртывание настроено через GitHub Actions (`.github/workflows/deploy.yml`: `npm ci` → `npm run build` → `actions/deploy-pages@v4`).

### 2.2. Аналитический отчёт (оценка рисков, рекомендация и обоснование)

При выборе бесплатной платформы для публикации статического сайта на Vue 3 и Vite ключевое значение приобретает не только удобство развёртывания, но и юридическая совместимость условий обслуживания с потенциальным размещением рекламы. Даже если на старте на сайте установлен лишь плейсхолдер `AdSlot.vue`, дальнейшее подключение рекламных сетей или партнёрских баннеров способно перевести проект из категории личного эксперимента в категорию монетизируемого ресурса. Недооценка этого перехода на бесплатных тарифах популярных хостингов создаёт прямой риск блокировки проекта или принудительного перевода на платный тариф.

#### Предупреждение о рисках политики использования
Наиболее жёсткую позицию в отношении рекламы и любой монетизации занимает **Vercel** на тарифе *Hobby*. Согласно официальным правилам платформы (*Vercel Fair Use Guidelines* и *Terms of Service for Hobby Plan*), бесплатный тариф предназначен исключительно для личного некоммерческого использования. Документация Vercel прямо относит подключение рекламных платформ (например, Google AdSense), сайты с основной целью размещения партнёрских ссылок, а также приём платежей за товары или услуги к коммерческой деятельности. Исключение делается только для добровольных пожертвований. Таким образом, публикация сайта с рекламными блоками на Vercel Hobby нарушает пользовательское соглашение и может привести к остановке проекта без предварительного коммерческого предупреждения.

Пограничную, так называемую «серую зону», образует **GitHub Pages**. В официальной документации (*About GitHub Pages — Prohibited uses*) закреплено, что сервис не предназначен для бесплатного хостинга онлайн-бизнеса, электронной коммерции или SaaS-сервисов, нацеленных на проведение коммерческих операций. Хотя правила допускают кнопки пожертвований (GitHub Sponsors, Patreon) и умеренное присутствие спонсорских баннеров в личных или open-source проектах, превращение сайта в площадку, ориентированную преимущественно на показ рекламы или сбор лидов, противоречит условиям обслуживания.

Отдельного внимания заслуживает **Netlify**. Хотя представители платформы допускают коммерческое и клиентское использование бесплатного плана, детальные нюансы сторонней рекламной монетизации не закреплены отдельным гарантированным пунктом для free-сегмента, а ключевым ограничением с 2026 года стала новая ресурсная модель **300 кредитов в месяц**. Поскольку каждый production-деплой списывает 15 кредитов, а каждый гигабайт трафика — 20 кредитов, активный сайт с рекламой и частыми обновлениями способен исчерпать месячный лимит за несколько дней, после чего платформа автоматически приостановит доступ к сайту до следующего расчётного периода.

На фоне конкурентов **Cloudflare Pages** и **Render Static Sites** выглядят наиболее предсказуемо с точки зрения политики. Условия *Cloudflare Self-Serve Subscription Agreement* не содержат запрета на коммерческие сайты или размещение сторонней рекламы на бесплатном тарифе Pages (ограничение касается лишь прямого сбора и обработки платёжных карт в рамках требований PCI DSS). Аналогично, **Render** не запрещает рекламу на статических сайтах, ограничивая лишь ежемесячный объём исходящего трафика порогом в 100 ГБ и время сборок 500 минутами на рабочее пространство.

#### Рекомендация для сценария «Vue-сайт + реклама»
Для публикации статического сайта на Vue 3 с возможностью последующего размещения рекламы **предпочтительной платформой является Cloudflare Pages**, а **резервной альтернативой — Render Static Sites** (либо GitHub Pages исключительно при сохранении некоммерческого статуса проекта). Cloudflare Pages сочетает полную юридическую безопасность размещения рекламных блоков с отсутствием лимитов на пропускную способность и число HTTP-запросов, что особенно важно при росте посещаемости. Платформа нативно поддерживает рабочий процесс Vite/Vue: автоматическое определение команды `npm run build`, директории `dist`, предпросмотр Pull Request и встроенную поддержку SPA-маршрутизации. Лимит в 500 бесплатных сборок в месяц с запасом покрывает цикл разработки и регулярного обновления контента, не заставляя экономить каждый коммит.

#### Обоснование решения: ключевые факторы выбора
1. **Приоритет соответствия правилам монетизации и рекламы.** Главный риск в данном сценарии — не технические сбои, а административная блокировка из-за нарушения условий тарифа. Выбор Cloudflare Pages полностью снимает юридические ограничения на интеграцию `AdSlot.vue` с реальными рекламными сетями в будущем, тогда как Vercel Hobby потребовал бы немедленной оплаты подписки Pro.
2. **Приоритет пропускной способности и предсказуемости лимитов.** Успешный сайт с рекламой напрямую заинтересован в росте трафика, поэтому жёсткая привязка трафика к кредитам (как 300 кредитов на Netlify) или потолок в 100 ГБ создают угрозу внезапного отключения сайта на пике посещаемости. Безлимитная раздача статики через глобальную сеть CDN Cloudflare гарантирует стабильную доступность ресурса без скрытых доплат.
3. **Приоритет автоматизации Git и совместимости с Vite/Vue.** Для современного фронтенда критична скорость CI/CD: при каждом `git push` платформа должна автоматически пересобирать бандл и разворачивать его с бесплатным SSL-сертификатом. В Cloudflare Pages настройка сводится к указанию `npm run build` и папки `dist` при стандартном `base: '/'`, что обеспечивает нулевую задержку между доработкой интерфейса на Tailwind CSS и публикацией новой версии в продакшен.
